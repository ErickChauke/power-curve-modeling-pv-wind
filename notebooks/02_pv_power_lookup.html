PV Power Lookup: PV1 & PV2¶

Erick Chauke

For PV1 and PV2, this notebook builds a lookup table from the measured grid (no fitting, no statistical model) and shows a few ways to look at the same data: a heatmap, a 3D surface, the table itself, and a nearest-measurement lookup function that answers "given this irradiance and module temperature, what did we actually measure closest to that?"

Looking Up a Value¶

Given an irradiance and module temperature that may or may not be exactly in the table, find the closest row already measured and use its power value.

In [6]:
sample_queries_pv1 = [(800, 40), (500, 20), (1200, 60)]
for irradiance_query, temp_query in sample_queries_pv1:
    result = nearest_lookup(table_pv1, "module_temp", "irradiance",
                             x_query=temp_query, y_query=irradiance_query)
    print(f"Query: irradiance={irradiance_query} W/m^2, module_temp={temp_query} C  ->  "
          f"closest measurement: irradiance={result['irradiance']:.0f}, "
          f"module_temp={result['module_temp']:.0f}, power={result['power']:.2f} MW")

A Limitation Worth Naming¶

A lookup only ever returns something that was actually measured, or the closest thing to it. For the corners of the grid that were never sampled (see 01_data_exploration.ipynb's missingness section, a cold module at high irradiance essentially never happens in the field), the nearest lookup will still return an answer, but that answer is the closest available measurement, not a real reading for that exact combination. That is a reasonable, honest limitation for a lookup table to have: it never invents a number, it just cannot answer for a condition that was never observed.
